# 커리어 03~06 통합 기록

## 대상

- `career-growth-plan`
- `career-track-pm-builder`
- `career-track-product-frontend`
- `career-market-demand`
- `career-artifacts`

## 진단

다섯 문서는 모두 같은 커리어 결정 루프의 일부였다.

- 성장 진단은 노선 선택의 입력이다.
- PM 겸 개발자/제품형 프론트엔드 노선은 서로 배타적 정체성이 아니라 공고별 포지셔닝 카드다.
- 시장 요구 분석은 노선 선택을 검증하는 근거다.
- 산출물 정리는 성장·노선·시장 판단의 실행 결과다.

별도 메뉴로 두면 `포지셔닝`, `면접 전략`, `자가 진단`, `우선순위`가 반복되고 사용자가 다음 행동을 고르기 어려워진다.

## 결정

`career-growth-plan-handbook.html`을 `성장·노선·시장·산출물 로드맵` 통합 페이지로 재작성한다.

메뉴에서는 아래 네 항목을 제거한다.

- `career-track-pm-builder`
- `career-track-product-frontend`
- `career-market-demand`
- `career-artifacts`

원본 HTML 파일은 통합 페이지에 핵심 내용을 흡수한 뒤 제거한다. `CAREER_HANDBOOKS`, 생성 문서, 검색 인덱스에는 통합 페이지 하나만 남긴다.

## 품질 기준

- 통합 페이지는 `진단 -> 노선 선택 -> 시장 근거 -> 산출물 지도 -> 90일 실행` 순서로 읽혀야 한다.
- 노선 A/B는 별도 자기소개가 아니라 공고별로 갈아 끼우는 카드로 설명한다.
- 시장 데이터는 절대 비율이 아니라 표본 기반 판단으로 표현한다.
- 산출물은 파일명, 공개 가능 범위, 면접 사용 방식까지 닫는다.
