# AI Native 훈련 추가 리뷰

작성일: 2026-07-03  
검토 범위: `AI Native 훈련` 그룹 6개 문서, 홈의 AI Native 진단, 기존 2026-07-01 리뷰/보강 계획

## 총평

현재 AI Native 훈련 문서는 이전보다 분명히 좋아졌다. 역량 매트릭스, 실습 랩, 템플릿 키트, 평가 하네스, 보안 레드팀, Agent Runtime까지 공식 그룹으로 분리되어 있고, 각 문서에는 산출물과 통과 기준이 들어 있다.

하지만 아직 "훈련 교재"라기보다는 "좋은 체크리스트 묶음"에 가깝다. 사용자가 느낀 문제는 타당하다. 표가 많고, 개념을 충분히 풀어 설명하기 전에 항목을 나열하며, 하나의 예시 프로젝트가 반복적으로 쌓이는 감각이 약하다. 중급 개발자가 읽으면 방향은 알 수 있지만, 초급~중급 전환 구간의 학습자는 왜 이 순서가 필요한지, 무엇을 실제로 만들어야 하는지, 어떤 제출이 통과인지까지 충분히 체감하기 어렵다.

## 핵심 문제

| 문제 | 현재 증상 | 영향 |
| --- | --- | --- |
| 추상도가 높음 | "평가", "보안", "운영", "증거화"가 빠르게 등장하지만 원리 설명이 짧음 | 개념을 아는 사람에게는 좋지만 처음 훈련하는 사람은 따라 하기 어렵다 |
| 표 중심 구성 | 많은 섹션이 표와 짧은 예시 코드로 구성됨 | 읽는 흐름이 끊기고 교재보다 레퍼런스처럼 느껴진다 |
| 프로젝트 맥락 부족 | Policy Document Intelligence Assistant가 나오지만 기능, 사용자, 데이터, 실패 사례가 충분히 구체화되지 않음 | 랩들이 같은 프로젝트 위에 누적된다는 감각이 약하다 |
| 예시 제출 부족 | 좋은 제출 예시는 있으나 before/after, 반려 예시, 리뷰 코멘트가 더 필요함 | 학습자가 자신의 제출물을 어떻게 개선할지 판단하기 어렵다 |
| best/bad practice가 산발적 | 일부 섹션에만 있음 | 모든 핵심 개념에서 "하면 안 되는 방식"을 체계적으로 학습하기 어렵다 |

## 개선 방향

1. 각 문서를 "개념 설명 → 예시 프로젝트 → 실습 → 제출 예시 → 리뷰 기준" 순서로 재구성한다.
2. 모든 AI Native 훈련 문서가 같은 capstone 프로젝트를 공유하게 한다.
3. 표는 요약용으로 쓰고, 중요한 개념은 문단으로 먼저 설명한다.
4. bad practice는 단순 금지 목록이 아니라 왜 실패하는지와 어떤 증거로 잡히는지를 함께 쓴다.
5. 실습 산출물은 파일명, 입력 fixture, 실행 명령, 통과 기준, reviewer note까지 포함한다.

## 우선 보강 대상

P0는 `ai-native-competency-map`과 `ai-native-labs`다. 이 두 문서가 훈련의 입구이므로 여기서 교재성이 약하면 뒤의 평가/보안/Agent 문서도 체크리스트처럼 소비된다.

P1은 `ai-native-evaluation-harness`, `ai-native-security-red-team`, `ai-native-agent-runtime`이다. 이 문서들은 이미 방향이 좋지만, 각자 작은 구현 예제와 반려 사례를 더 넣어야 한다.

P2는 `ai-native-toolkit`과 커리어/포트폴리오 연결이다. 템플릿은 충분히 많으므로 다음 개선은 템플릿을 채운 완성본과 빈칸이 많은 실패본을 나란히 보여주는 것이다.
