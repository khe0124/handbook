# 커리어 문서 목적별 재분류

## 원칙

취업에서는 검증된 FE 경력을 기준으로 역할과 팀을 고르고, 개인 작업에서는 미감·도메인 이해·구현을 보여주는 작품 하나를 병행한다. 두 트랙은 서로의 선행 조건이 아니다. 핸드북 분량보다 제출·동작하는 결과·피드백을 우선한다.

문서 ID와 파일명은 기존 저장 위치·문서 선택 상태를 위해 유지한다. 제목과 순서는 목적에 맞춰 바꾼다. HTML 원본은 `public/handbook`, 앱 본문과 검색 인덱스는 `node scripts/handbook-html.mjs`로 생성한다.

## 주요 이동·통합

- 이력의 포지션 우선순위·강점/취약점 → 02의 `position-evidence`, `strength-gap`.
- 이력의 질문별 증거·답변 카드 → 06의 `history-evidence-map`, `history-answer-cards`.
- 회사 조사·역질문 → 02의 `company-q2`, `company-q11`.
- 성장 로드맵의 산출물 지도 → 05의 `artifact-map`.
- 장기 목표의 2016–2019 시각 아카이브 → 05의 `visual-archive`.
- 컬처 문서의 B2B 어드민 증거·운영자 UX·답변·도메인 깊이 → 10의 `personalb2b-ch2/3/4/6`. Senior IC 협업 판단은 15에 유지.
- 일반 성장 서사·이력서 요약·백엔드 전환 문구·중복 학습 일정을 통합. 실제 백엔드 구현 증거와 충돌하던 초기 “학습 단계” 일반론은 제거.
- AI를 이용해 개발하는 것과 제품 자체의 모델 호출을 분리. 모델 평가·프롬프트 인젝션·토큰 비용 기록은 후자에만 적용. 예시 지표는 가상 수치로 표시.

## 유지보수

- 프로젝트 사실·기여 경계와 기술 심화 문항은 보존한다. 날짜·수량·기술 버전은 이번 재분류에서 재검증하지 않았으며 제출 전에 원자료와 대조한다.
- 이전 분류에 속한 단원은 이동하면서 앵커가 바뀔 수 있다. 현재 목차·문서 간 링크·검색 인덱스는 새 소유 문서를 가리킨다.
- 공개 HTML 간 링크와 앱 내 연결은 같은 문서·단원으로 이동한다. 앱은 `data-handbook-section`을 처리한다.
- 과거 원문 합치기 도구 `generate-engineering-bundles.mjs`는 수작업으로 분류한 커리어 문서를 덮어쓰지 않는다. 기존 인터뷰·개인화 원문 파일은 보존한다.
- `scripts/career-organization.test.mjs`는 목차·문서 링크·단원별 단일 소유·옛 참조 제거를 검사한다. 전체 원본과 생성물의 일치는 기존 테스트로 검증한다.
