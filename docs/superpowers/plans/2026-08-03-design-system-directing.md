# Design System Directing Document Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one new leaf document (`09 디자인시스템 거버넌스·디렉팅`) to the `디자인` menu, covering how a design lead directs (not personally executes) a design system rollout: governance, stakeholder buy-in, launch strategy, and designer-engineer collaboration.

**Architecture:** This codebase's handbook content is authored as static HTML in `public/handbook/<id>-handbook.html` (canonical source, per `README.md`), and the React app loads a derived TypeScript module `src/handbook/documents/<id>.ts` (extracted `navHtml`/`mainHtml`, glob-imported by `src/handbook/documentLoaders.ts`). We author the public HTML, then use the already-tested `extractHandbookDocument()` helper (`scripts/handbook-html.mjs`) to mechanically produce the `.ts` module for this one id only.

**Tech Stack:** Vite + React 19 + TypeScript, plain HTML/CSS content strings, `node:test`/`node:assert` for verification (`npm test`), Vite build (`npm run build`).

## Global Constraints

- Spec: `docs/superpowers/specs/2026-08-03-design-system-directing-design.md`.
- id: `design-system-directing`. label: `"09 디자인시스템 거버넌스·디렉팅"`. kind: `"디자인"`. file: `"design-system-directing-handbook.html"`.
- 10 sections in this exact order: `system-directing-map` (MAP), `governance` (GOV), `stakeholder-buyin` (STAKE), `rollout-strategy` (ROLLOUT), `design-eng-collab` (COLLAB), `team-structure` (TEAM), `health-metrics` (METRICS), `failure-patterns` (RISK), `glossary` (GLOSSARY), `output-verification-standards` (VERIFY).
- Markup convention per section: `<section id="...">` wrapping `<div class="ch-head"><span class="ch-code">CODE</span><h2>Title</h2></div>`, a `<p class="lede">...</p>` intro, then at least one `<table>` and one `<div class="callout"><span class="co-label">...</span><p>...</p></div>`; sections that describe a sequence also get a `<div class="flow">` step chain (`<span class="step">...</span><span class="arr">→</span>`).
- Document wrapper: `<!doctype html><html lang="ko"><head>...<title>...</title></head><body><div class="shell"><nav aria-label="목차">...</nav><main><header class="hero">...</header>[sections]<footer>...</footer></main></div></body></html>`.
- **CRITICAL — do NOT run `npm run generate:handbook`.** That script (`scripts/handbook-html.mjs`, direct-run block) regenerates `src/handbook/documentLoaders.ts` from a template that has no awareness of the quiz/roadmap loaders (`buildQuizLoader`, `ROADMAP_PAGE_LOADERS`, `QUIZ_TOOL_PAGE_LOADERS`) added in commit `8f6517d`. Running it would silently delete that logic and break quiz/roadmap pages. This plan only ever calls the exported `extractHandbookDocument()` function directly, scoped to this one new file — never the script's direct-run path.
- Do not touch `src/handbook/documentLoaders.ts` or `src/handbook/searchIndex.mjs` in this plan.
- The `디자인` group is already in `NON_STUDY_GROUP_KEYS` (`src/handbook/catalog.mjs`), so this new id is automatically excluded from `NON_STUDY_DOC_IDS`'s complement (study/SRS/global-search scope) — no extra wiring needed there.
