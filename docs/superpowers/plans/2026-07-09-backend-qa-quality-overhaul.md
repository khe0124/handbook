# Backend Q&A Quality Overhaul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the backend Q&A generated filler with topic-specific answers across all backend menu Q&A documents.

**Architecture:** The generator remains the source of truth, but generic coverage generation must stop producing shipped answers. Each backend Q&A question will carry explicit follow-up answer content. Rendering will use explicit answers and fail loudly if a question lacks them.

**Tech Stack:** Node ESM generator scripts, static HTML handbooks, generated TypeScript document modules, Node test runner.

## Task 1: Add A Failing Quality Gate

**Files:**
- Modify: `scripts/handbook-html.test.mjs`

- [ ] **Step 1: Add a backend Q&A duplicate-followup test**

Add a test that reads every backend Q&A public HTML file and extracts every `qa-*` section. For each section, parse follow-up answer cells and fail if:

```js
const normalizedAnswers = answers.map((answer) =>
  answer.replace(/\s+/g, " ").trim(),

assert.equal(
  new Set(normalizedAnswers).size,
  normalizedAnswers.length,
  `${item.file} ${sectionId} should not repeat follow-up answers`,
);
```

## Task 2: Change The Generator Contract

**Files:**
- Modify: `scripts/generate-backend-qa-handbooks.mjs`

- [ ] **Step 1: Introduce explicit follow-up answer shape**

Support questions with:

```js
followups: [
  { q: "401, 403, 404를 언제 구분하나요?", answer: "..." },
  { q: "목록 API와 상세 API의 인가 누락은 어떻게 다르게 나타나나요?", answer: "..." },
  { q: "관리자 권한은 role만 보면 충분한가요?", answer: "..." },
],
```

- [ ] **Step 2: Update rendering to require explicit answers**

In `renderQuestion`, convert follow-ups with:

```js
const followupRows = question.followups.map((followup) => {
  if (typeof followup === "string") {
    throw new Error(`Missing explicit follow-up answer for ${question.q}: ${followup}`);
  }
  if (!followup.q || !followup.answer) {
    throw new Error(`Invalid follow-up for ${question.q}`);
  }
  return `<tr><td>${escapeHtml(followup.q)}</td><td>${escapeHtml(followup.answer)}</td></tr>`;
});
```

- [ ] **Step 3: Remove rendered dependency on `answerFollowup()`**

Do not call `answerFollowup()` from rendering. Leave helper rules only temporarily if needed for migration, but no page may render through fallback.

- [ ] **Step 4: Run generator and verify it fails**

Run:

```bash
node scripts/generate-backend-qa-handbooks.mjs
```

Expected: FAIL until all questions have explicit follow-up answers.

## Implementation Strategy

Use subagent-driven execution by document group:

1. One worker rewrites Backend Core.
2. One worker rewrites Auth/Security.
3. One worker rewrites Architecture.
4. One worker rewrites Data.
5. One worker rewrites Runtime.
6. One worker rewrites Platform Tools.
7. One worker rewrites Java/Spring.

Because all groups currently live in one generator file, direct parallel editing would conflict. Execute workers in sequence or split the generator into per-page data modules before parallel writing.

Recommended first refactor:

- Create `scripts/backend-qa-data/*.mjs`, one file per Q&A page.
- Keep `scripts/generate-backend-qa-handbooks.mjs` as renderer/orchestrator.
- Then document-specific workers can edit disjoint data files safely.
