Interaction Engineering

사용자의 입력 신호를 의도와 상태 변화로 해석하고 즉시 이해되는 피드백으로 되돌리는 법

INTERACTIVE WEB MASTERY · UPDATED 2026-10
START

인터랙션의 구조

이벤트는 사용자의 의도가 아니다. pointermove는 좌표가 변했다는 신호일 뿐이고, 제품은 여러 신호를 시간과 거리 기준으로 해석해 tap, drag, swipe, hold 같은 의도를 추론해야 한다.

핵심 모델

Input → Sample → Normalize → Recognize → State → Feedback으로 본다. 브라우저 이벤트에서 좌표·시간·압력·pointer type을 수집하고 같은 좌표계와 단위로 정규화한다. 그 다음 threshold와 상태 규칙으로 gesture를 판별하고, 제품 state를 바꾼 뒤 시각·텍스트·촉각 피드백을 제공한다. 취소, 다중 입력, scroll 충돌, keyboard 대체 경로까지 포함해야 하나의 완결된 인터랙션이다.

층위질문예시
Input무슨 신호가 들어왔는가pointerdown, wheel, keydown
Intent사용자는 무엇을 하려는가선택, 이동, 탐색, 확대
State시스템은 지금 어떤 단계인가idle, pressed, dragging, settling
Feedback입력과 결과가 이해되는가pressed style, live position, snap
Outcome업무 결과가 완료됐는가순서 변경, 카드 삭제, 다음 slide
01

Event와 사용자 의도

한 개의 event로 gesture를 확정하지 않는다. 시작 위치, 경과 시간, 누적 거리, 주 방향, 속도, 종료 조건을 함께 보고 의도를 판별한다.

후보 gesture판별 신호대표 사례오인 방지
Tap짧은 시간, 작은 거리button, card 선택drag threshold를 넘으면 취소
Double tap두 tap의 시간·거리 근접지도 확대, media likesingle tap 지연 비용 검토
Hold일정 시간 동안 threshold 안에 머묾context menu, reorder 시작move·cancel에서 timer 정리
Dragpressed 상태에서 거리 threshold 초과slider, card 이동scroll 방향과 axis lock
Swipe종료 시 거리와 속도 충족carousel, dismiss거리 하나만으로 판정하지 않음
Pinch두 pointer 사이 거리 변화map, image zoompointerId별 sample 관리
02

Pointer Events와 Capture

Pointer Events는 mouse, touch, pen을 하나의 이벤트 모델로 다룬다. pointerId로 입력을 구분하고 pointerType, pressure, 버튼 상태를 필요할 때 사용한다.

function onPointerDown(event) {
  if (!event.isPrimary || event.button !== 0) return;
  event.currentTarget.setPointerCapture(event.pointerId);
  drag = { id: event.pointerId, startX: event.clientX, lastX: event.clientX };
}

function onPointerMove(event) {
  if (!drag || event.pointerId !== drag.id) return;
  updateDrag(event.clientX - drag.startX);
  drag.lastX = event.clientX;
}

function endPointer(event) {
  if (drag?.id !== event.pointerId) return;
  event.currentTarget.releasePointerCapture(event.pointerId);
  settleOrCancel();
  drag = null;
}
Event의미필수 처리
pointerdown상호작용 후보 시작대상, pointerId, 시작 좌표·시간 저장
pointermovesample 추가threshold 전에는 tap 후보 유지
pointerup정상 종료gesture 결정, capture 해제, settle
pointercancel브라우저가 입력 stream 취소결과 commit 금지, timer·capture·style 정리
lostpointercapture소유권 종료남은 dragging state 복구
03

좌표계와 정규화

좌표 버그는 수학보다 기준 공간을 섞어서 발생한다. 이벤트 좌표가 screen, viewport, document, element local 중 어디에 있는지 먼저 표시하고 같은 공간으로 변환한 뒤 계산한다.

좌표기준주요 사용
screenX / Y물리적 화면웹 UI 계산에는 거의 사용하지 않음
clientX / Y현재 viewportelement rect, pointer UI
pageX / Ydocumentpage scroll을 포함한 위치
offsetX / Yevent target 기준target이 바뀌면 기준도 바뀌어 drag에 주의
local선택한 element 내부canvas, slider, shader uniform
NDC-1–1 정규화 장치 좌표WebGL raycasting
const rect = element.getBoundingClientRect();
const localX = event.clientX - rect.left;
const localY = event.clientY - rect.top;
const nx = Math.max(0, Math.min(1, localX / rect.width));
const ny = Math.max(0, Math.min(1, localY / rect.height));

// WebGL normalized device coordinates
const ndcX = nx * 2 - 1;
const ndcY = 1 - ny * 2;
04

Gesture Recognition은 상태 기계다

gesture는 event handler 묶음이 아니라 시간이 흐르며 후보를 좁히는 상태 기계다. Tap 후보로 시작해 이동 threshold를 넘으면 Drag로 전환하고, 중간에 browser cancel이 오면 결과 없이 Cancelled로 끝낸다.

switch (state.phase) {
  case "pressed":
    if (distance(start, current) > DRAG_THRESHOLD) {
      state = { phase: "dragging", pointerId, origin: current };
    }
    break;
  case "dragging":
    state = { ...state, position: clampToBounds(current) };
    break;
}
Gesture arbitration

가로 carousel 안에서 세로 page scroll도 가능하다면 첫 move에서 무조건 preventDefault()하지 않는다. 충분한 거리를 관찰해 주 방향을 판별하고, 가로 drag로 확정된 뒤에만 해당 gesture가 소유권을 갖게 한다. CSS touch-action도 의도한 native gesture와 함께 설계한다.

05

Drag와 Swipe

Drag는 pointer 위치를 UI 값에 연속 매핑하고, Swipe는 종료 순간의 거리와 속도로 다음 상태를 결정한다. 같은 입력 stream을 쓰지만 결과를 결정하는 시점이 다르다.

const dx = current.x - previous.x;
const dt = Math.max(current.time - previous.time, 1);
const velocityX = dx / dt;

const shouldAdvance =
  Math.abs(totalX) > width * 0.35 || Math.abs(velocityX) > 0.5;

const target = shouldAdvance
  ? index + Math.sign(-totalX)
  : index;
설계 요소질문실패 사례
Hit target손가락과 pen으로 잡기 충분한가시각 크기만큼만 hit area 제공
Thresholdtap과 drag를 안정적으로 구분하는가1px 움직임에 click 취소
Constraint경계 밖에서 resistance가 있는가콘텐츠가 영구히 viewport 밖으로 이탈
Velocity최근 sample을 사용해 release 의도를 반영하는가전체 평균으로 마지막 flick 무시
Snap목표가 예측 가능하고 중간에 다시 잡히는가animation 중 pointer 입력 잠금
Fallback버튼·키보드로 같은 결과를 얻는가swipe만 가능한 carousel
06

Scroll은 탐색 입력이다

Scroll position 자체보다 구간을 0–1 progress로 정규화한 값이 재사용하기 쉽다. 같은 progress를 scale, opacity, camera position에 매핑할 수 있지만 사용자의 탐색권을 빼앗아서는 안 된다.

const progress = clamp(
  (scrollY - sectionStart) / (sectionEnd - sectionStart),
  0,
  1
);

const scale = lerp(0.82, 1, progress);
const opacity = lerp(0.35, 1, progress);
필요우선 도구사례이유
보이는지 여부IntersectionObserverlazy load, 한 번 reveal연속 scroll listener 불필요
선언형 progressCSS scroll/view timelineprogress bar, view revealscroll을 animation timeline에 직접 연결
연속 custom 계산rAF samplingcanvas, WebGL camera여러 입력과 simulation 결합
복잡한 pin과 sequenceScrollTrigger 등editorial narrative구간 debug와 choreography
Scroll hijacking

휠의 이동량을 임의 페이지 전환으로 바꾸거나 긴 pin으로 탈출을 막으면 trackpad, keyboard, screen reader, browser history와 충돌할 수 있다. 콘텐츠 관계를 설명하는 명확한 이유가 없다면 native scroll을 유지한다.

07

Feedback과 접근성

좋은 인터랙션은 입력 즉시 반응하고, 조작 중 현재 상태를 보여주며, 완료와 실패를 명확히 구분한다. 움직임 하나에 의미를 전부 맡기지 않는다.

Pointer 목표Keyboard 대안Semantic 상태
Carousel swipe이전·다음 button, Arrow keys현재 slide와 전체 개수
Drag reorder잡기·이동·놓기 command이동 결과 live announcement
Slider dragArrow, PageUp/Down, Home/End현재 값, 범위, 단위
Long press menu명시적 menu button, Shift+F10expanded와 focus 이동
Scroll reveal모션 없이도 DOM 순서로 접근숨긴 콘텐츠가 focus를 막지 않음
08

성능과 충돌 처리

pointermove는 화면 refresh보다 더 자주 발생할 수 있다. event마다 DOM을 그리지 말고 최신 sample을 저장한 뒤 다음 animation frame에서 한 번 렌더링한다.

let latestPointer = null;
let framePending = false;

function onPointerMove(event) {
  latestPointer = { x: event.clientX, y: event.clientY, time: event.timeStamp };
  if (framePending) return;
  framePending = true;
  requestAnimationFrame(() => {
    framePending = false;
    renderFrom(latestPointer);
  });
}
충돌원인해결
Drag vs scroll주 방향 판별 전 gesture 소유threshold + axis lock + touch-action
Child vs parent drag중첩 recognizer가 같은 입력 처리명시적 owner와 propagation 계약
Click after dragup 이후 click이 추가 발화dragged flag와 semantic activation 분리
Resize during drag오래된 rect와 constraintresize policy와 geometry refresh
Multi-touch intrusionprimary pointer 가정 붕괴pointerId map 또는 추가 입력 무시 정책
Component removalcapture, timer, listener 잔존cancel 경로 하나로 cleanup 통합
09

의사결정표

  1. 사용자가 달성하려는 결과를 문장으로 쓴다.
  2. pointer, keyboard, scroll 중 가능한 입력 경로를 나열한다.
  3. raw event를 정규화할 좌표·시간·단위를 정한다.
  4. tap·drag·swipe의 threshold와 상호 배타 규칙을 정한다.
  5. idle부터 cancel·settling까지 state machine을 그린다.
  6. 입력 수신·조작 중·결과·오류 feedback을 연결한다.
  7. resize, pointercancel, rapid re-entry, reduced motion을 실패시킨다.

구현 실습

Lab 1 Pointer Capture Drag Card

카드를 element 밖으로 끌고 나간 뒤 놓아도 정상 종료되게 한다. pointercancel, Escape, unmount에서 원래 자리로 복구하고 keyboard 이동 버튼을 제공한다.

Lab 2 Swipe Carousel

거리와 release velocity를 함께 사용한다. 세로 scroll과 충돌하지 않게 axis lock을 구현하고 이전·다음 버튼 및 현재 slide label을 제공한다.

Lab 3 Scroll Progress Image

section의 start와 end를 기준으로 0–1 progress를 만들고 image scale에 매핑한다. resize, zoom, 긴 콘텐츠 삽입 후에도 구간이 맞는지 검사한다.

Lab 4 Canvas 또는 WebGL Pointer Mapping

client 좌표를 element local과 NDC로 변환한다. CSS scale과 고해상도 canvas backing store에서도 pointer와 실제 drawing 위치가 일치해야 한다.

숙련 판정

  1. event와 gesture의 차이를 실제 sample sequence로 설명할 수 있는가?
  2. pointer capture가 필요한 이유와 해제해야 하는 모든 경로를 말할 수 있는가?
  3. client, page, local, NDC 좌표를 상황에 맞게 변환할 수 있는가?
  4. tap, hold, drag, swipe가 충돌하지 않는 state machine을 설계했는가?
  5. drag 중 scroll, resize, pointercancel, 두 번째 pointer가 들어와도 복구되는가?
  6. move event 수와 render 수를 분리하고 frame 단위로 update하는가?
  7. keyboard, focus, semantic state로 pointer와 같은 업무 결과를 제공하는가?
최종 기준

새로운 인터랙션을 보았을 때 이벤트 이름을 찾는 데서 시작하지 않고, 입력 sample, 좌표 변환, intent threshold, state transition, feedback, cancellation contract로 분해해 재설계할 수 있어야 한다.
