PORT-02

JD 키워드 매핑

JD 키워드보여줄 증거
RAGretrieval eval report, chunking tradeoff, citation failure analysis
LLM evaluationeval dataset, baseline/candidate report, CI gate
Agent/tool usetool contract, approval policy, audit trace
AI securityprompt injection fixture, tenant isolation test, red-team report
LLM operationsdashboard spec, SLO, incident packet, fallback plan

대표 capstone인 Policy Document Intelligence Assistant를 포트폴리오로 쓴다면, JD 키워드를 기능 이름에 매핑하지 말고 증거에 매핑합니다. RAG는 “문서 검색 챗봇”이 아니라 retrieval trace와 citation failure analysis로, evaluation은 “테스트했다”가 아니라 baseline/candidate gate로, security는 “API key를 숨겼다”가 아니라 indirect injection과 tenant isolation fixture로 보여줘야 합니다.

EVIDENCE

증거·과장 방지 기준

커리어 답변은 강하게 말하되 증거가 받쳐 주는 범위 안에서만 말한다. 수치, 역할, 성과, 장애 대응 경험은 원천 증거와 공개 가능 범위를 먼저 정한 뒤 답변에 넣는다.

항목기준금지선
수치커밋, 기간, 사용자 수, 성능 개선율은 산정 기준과 기간을 함께 말한다.추정치를 확정 성과처럼 말하지 않는다.
역할직접 구현, 공동 설계, 리뷰 참여, 운영 보조를 구분한다.팀 성과를 단독 성과로 바꾸지 않는다.
증거 위치Git log, PR, ticket, dashboard, release note, 회고 문서 중 하나 이상에 연결한다.공개할 수 없는 내부 정보를 화면 캡처나 원문으로 노출하지 않는다.
공개 범위공개 가능, 익명화 필요, 면접 구두 설명만 가능, 비공개를 구분한다.NDA, 고객명, 보안 설정, 매출·트래픽 원문을 임의로 공개하지 않는다.
답변 기준

말해도 되는 범위는 “내가 한 행동, 관찰한 문제, 확인 가능한 결과, 배운 점”이다. 모르는 수치나 비공개 지표는 “정확한 원문 수치는 공개할 수 없지만, 개선 방향과 검증 방식은 설명할 수 있습니다”라고 경계를 둔다.
