PHP-01

전체 생명주기와 산출물

웹에이전시 프로젝트는 코딩보다 소유권·콘텐츠·도메인·호스팅·외부 계정의 경계를 먼저 닫아야 합니다. 특히 기존 사이트 리뉴얼은 보이지 않는 폼, 관리자 기능, 검색 유입 URL, 메일 발송, CRM 연동을 잃지 않는 일이 핵심입니다.

AGENCY DELIVERY LIFECYCLE

문의·현황 조사 → 계정·소유권 확인 → 범위·견적·계약 → 백업·개발환경 → IA·데이터·권한 설계 → 구현 → 콘텐츠 이관 → 통합·보안·성능 테스트 → 고객 검수 → DNS·SSL·배포 → 안정화 → 유지보수·인수인계. 각 단계는 다음 단계에 필요한 입력과 승인자를 명확히 하고, 실패했을 때 이전 상태로 돌아갈 증거를 남겨야 완료됩니다.

PHP-02

착수·인수 조사

FTP 비밀번호 하나를 받았다고 인수가 끝난 것이 아닙니다. 도메인 등록자, DNS, 호스팅, SSL, 메일, DB, 소스, 관리자, analytics, 검색도구, 문자·메일·CRM 계정의 실제 소유자를 확인합니다.

조사 축확인 항목위험 신호
소유권도메인 명의, Cafe24 대표 계정, 결제자, 2FA 복구 수단퇴사자 개인 계정·개인 카드

데이터DB 수, 문자셋, 개인정보, 업로드, 보존·삭제 요구평문 비밀번호·민감정보 무기한 보관

FIRST ACTION

수정 전에 파일과 DB를 각각 백업하고 복구 시험을 합니다. 백업 파일이 생성됐다는 사실과 실제로 복원할 수 있다는 사실은 다릅니다.

PHP-03

요구사항·견적·계약

“홈페이지 리뉴얼”은 범위가 아닙니다. 페이지 수, 언어, 콘텐츠 입력 주체, 관리자 기능, 데이터 이관, 외부 연동, SEO 보존, 브라우저 기준, 검수 횟수, 운영 지원을 수량과 완료 조건으로 바꿉니다.

범위 항목결정 질문견적 단위 예시

계약서에는 산출물 소유권, 유료 theme/plugin/license 귀속, 계정 명의, 제3자 비용, 데이터 제공 책임, 검수 기간, 변경 요청 단가, 하자와 유지보수의 구분, 종료 시 인계 항목을 명시합니다.

PHP-08

AJAX·프론트엔드 연동

AJAX는 jQuery 호출 문법이 아니라 HTTP 계약입니다. 브라우저 검증은 UX이고 신뢰 경계는 PHP 서버입니다. 모든 mutation은 인증·권한·CSRF·validation·idempotency를 다시 확인합니다.

fetch('/api/inquiries', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'X-CSRF-Token': csrfToken },
  body: JSON.stringify(payload),
  credentials: 'same-origin'
});

PHP-11

Apache·.htaccess

공유호스팅에서는 서버 전역 설정을 바꿀 수 없어 .htaccess로 rewrite·접근 제한·일부 헤더를 설정하는 경우가 많습니다. VPS처럼 전역 설정 권한이 있다면 성능과 통제 면에서 VirtualHost 설정을 우선합니다.

Options -Indexes
RewriteEngine On

# 실제 파일과 디렉터리는 그대로 제공
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ index.php [L,QSA]

# 민감한 파일 접근 차단
<FilesMatch "^(\.env|composer\.(json|lock)|.*\.sql)$">
  Require all denied
</FilesMatch>
