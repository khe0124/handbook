SEC-00

공개면 줄이기

인터넷에 공개되는 것은 DNS record, CDN, WAF, Load Balancer 정도로 제한한다. App, DB, cache, queue는 private subnet에 두고 관리 접근은 VPN, bastion, SSO, short-lived credential로 제한한다.

OPERATIONS DECISION

운영 질문 인터넷 공개면이 의도한 edge 계층으로 제한되어 있는가?

확인할 증거 public DNS record, CDN/WAF distribution, LB listener, security group ingress, admin access path

판단 기준 App/DB/cache/queue가 public endpoint 없이 private 경계 안에 있어야 한다.

배제 확인 공개면 줄이기를 원인 후보에서 배제하려면 어떤 확인 결과가 필요한가?

확인 위치 external scan, DNS inventory, LB listener list, SG ingress, bastion/VPN access log

명령 해석 외부에서 접근 가능한 표면을 실제로 열거해야 한다.

임시 완화와 영구 수정 관리 포트 또는 내부 앱이 인터넷에 노출됨 기준으로 영향 범위를 좁히고, public ingress를 닫고 edge/WAF/LB 경로로만 접근하게 복구한다.

SEC-01

WAF와 방화벽

WAF는 L7의 악성 요청 패턴을 줄이고, security group은 stateful L4 허용 목록을 만든다. NACL은 stateless subnet 경계라 응답 포트까지 고려해야 한다. 차단 로그가 남지 않는 규칙은 운영 중 원인 분석을 어렵게 만든다.

OPERATIONS DECISION

운영 질문 WAF, security group, NACL이 각 계층 책임에 맞게 동작하는가?

확인할 증거 WAF rule hit, SG stateful rule, NACL stateless rule, firewall deny log, false positive rate

판단 기준 L7 차단과 L4 허용 목록, subnet stateless 경계를 혼동하지 않아야 한다.

배제 확인 WAF와 방화벽을 원인 후보에서 배제하려면 어떤 확인 결과가 필요한가?

확인 위치 WAF log, SG rule diff, NACL ephemeral port, firewall decision log

명령 해석 차단 로그 없이 규칙만 있으면 운영 중 원인 분석이 어렵다.

임시 완화와 영구 수정 정상 고객 요청이 WAF rule에 차단됨 기준으로 영향 범위를 좁히고, rule rollback, allow exception expiry, false positive 재튜닝을 기록한다.

SEC-02

IAM과 secret

IAM은 사람, 서비스, pipeline, workload identity를 분리한다. secret은 repo, image, log, frontend bundle에 들어가면 안 된다. rotation 절차에는 revoke, 재발급, 배포, 영향 범위 확인이 포함된다.

OPERATIONS DECISION

운영 질문 IAM과 secret이 사람·서비스·pipeline 경계별로 분리되어 있는가?

확인할 증거 principal, role assumption, policy diff, secret version, rotation date, last-used

판단 기준 장기 key와 wildcard 권한은 예외 승인과 만료 조건이 필요하다.

배제 확인 IAM과 secret를 원인 후보에서 배제하려면 어떤 확인 결과가 필요한가?

확인 위치 IAM access analyzer, policy diff, secret manager version, audit log, deploy consumer list

명령 해석 secret이 repo/image/log/frontend bundle에 남지 않아야 한다.

임시 완화와 영구 수정 secret rotation 후 일부 pod 인증 실패 기준으로 영향 범위를 좁히고, revoke, 재발급, consumer 재시작, 영향 범위 확인을 순서대로 수행한다.

SEC-03

검증 질문

위협 모델링은 public ingress, 인증 우회, 권한 상승, secret 노출, egress 악용, 로그 공백을 먼저 본다. 이 서비스의 public ingress는 어디인가? egress는 어떤 도메인과 포트까지 허용되는가? 관리자 권한은 누가 승인하고 얼마나 유지되는가? 침해 시 어떤 로그로 행위를 추적할 수 있는가?

OPERATIONS DECISION

운영 질문 위협 모델이 public ingress, auth, privilege, egress, log gap을 다루는가?

확인할 증거 public ingress list, auth boundary, admin action log, egress allowlist, audit coverage

판단 기준 공격 경로와 탐지 증거가 함께 설명되어야 한다.

배제 확인 검증 질문을 원인 후보에서 배제하려면 어떤 확인 결과가 필요한가?

확인 위치 threat model review, access review, WAF/auth/admin/egress log sample

명령 해석 통제는 차단뿐 아니라 조사 가능한 로그로 증명되어야 한다.

임시 완화와 영구 수정 비정상 admin export 후 행위 추적 로그 부족 기준으로 영향 범위를 좁히고, 권한 축소, egress 차단, audit alert, runbook diff를 남긴다.

CHECK

실무 체크리스트

보안 경계 체크리스트는 공개면 줄이기, WAF와 방화벽, IAM과 secret, 검증 질문에서 놓치기 쉬운 운영 증거를 작업 전후로 고정하기 위한 검토표다. 각 항목은 프론트엔드 증상, 배포 승인, 운영 인수에서 같은 기준으로 다시 확인한다.

  • public ingress를 DNS, CDN/WAF, Load Balancer로 제한한다.
  • IAM은 사람, workload, pipeline 권한을 분리한다.
  • secret은 repo, image, log, frontend bundle에 남지 않게 한다.
  • 위협 모델링으로 인증 우회, 권한 상승, egress 악용을 점검한다.
설계작업 단계

필수 산출물 목적, 영향 범위, 비목표, owner

차단 기준 영향 범위가 사용자·시스템·비용 기준으로 설명되지 않음

변경작업 단계

필수 산출물 diff, 승인 기록, 검증 명령

차단 기준 production 변경과 staging 검증의 차이가 설명되지 않음

복구작업 단계

필수 산출물 rollback 또는 forward fix, 담당자, 예상 시간

차단 기준 실패 시 되돌릴 수 없는데 사전 승인과 공지가 없음

PLAYBOOK

실무 플레이북

보안 경계 플레이북은 SECURITY BOUNDARY OPERATIONS PLAYBOOK 기준으로 증상, 범위, 최근 변경, 계층별 증거를 연결한다. 목표는 명령어를 많이 아는 것이 아니라 어느 가설을 버리고 어떤 완화책을 선택할지 설명하는 것이다.

SECURITY BOUNDARY OPERATIONS PLAYBOOK 1 symptom → 2 scope → 3 recent change → 4 evidence
→ 5 mitigation → 6 verification → 7 runbook diff
1 · 증상symptom
무엇이 안 되는가를 사용자 관점 한 문장으로. "느리다"가 아니라 어떤 요청이 언제부터 어떻게 실패하는지 적는다
2 · 영향 범위scope
전체인가 일부인가. region·tenant·경로·클라이언트 중 무엇으로 갈리는지가 가설의 절반을 지운다
3 · 최근 변경recent change
직전 배포, 설정·권한 변경, 인증서·route 교체를 같은 시간축에 올린다. 대부분의 장애는 최근 변경에서 온다
4 · 증거evidence
어느 경계에서 끊겼는지 deny 로그로 확인한다. SG·NACL·WAF 규칙과 IAM 권한을 실제 요청의 source·destination·port로 대조한다
5 · 완화mitigation
오탐이면 좁은 예외를 시한부로 열고, 공격이면 범위를 넓혀 차단한다. 넓게 여는 조치일수록 만료를 먼저 정한다
6 · 복구 검증verification
완화가 실제로 먹혔는지 같은 증거로 다시 확인한다. 사용자 경로를 한 번 통과시켜야 끝난 것이다
7 · 런북 갱신runbook diff
이번에 내린 판단을 문서에 되돌린다. 다음 사람이 같은 순서를 다시 발명하지 않게 하는 단계
Public ingress운영 표면

볼 증거 DNS, CDN/WAF, LB listener, allowed path, rate limit

판단 기준 공개면은 의도한 edge 계층으로 제한한다.

Identity / Secret운영 표면

볼 증거 IAM principal, role assumption, secret location, rotation record

판단 기준 장기 key와 wildcard 권한은 예외로 관리한다.

Auditability운영 표면

볼 증거 WAF log, auth failure, admin action, egress log, exception expiry

판단 기준 차단과 허용의 근거가 나중에 조사 가능해야 한다.

공개면 점검확인 단계

명령·확인 위치 DNS record, LB listener, WAF rule, security group ingress 목록화

해석 기준 인터넷에서 접근 가능한 표면을 실제로 열거한다.

권한 점검확인 단계

명령·확인 위치 IAM policy diff, last-used, access review, break-glass ticket

해석 기준 필요 권한과 사용된 권한의 차이를 본다.

비밀 점검확인 단계

명령·확인 위치 secret manager version, rotation date, deploy consumer, log redaction

해석 기준 secret이 repo/image/log/frontend bundle에 남지 않아야 한다.

PRACTICE

출력 판독 훈련

보안 경계는 개념을 아는 것보다 실제 출력에서 정상과 비정상을 구분하는 훈련이 중요하다. 아래 lab은 명령, 출력, 판단, 완화, 영구 수정을 한 번에 연결한다.

PRACTICE LAB 01 · IAM 권한 확대 diff 판독

배포 pipeline role에 임시 권한을 추가한 뒤 보안 리뷰가 들어왔다.

Command / Query

iam policy diff
- s3:GetObject arn:aws:s3:::app-config/*
+ s3:*
+ kms:Decrypt *
lastUsed=never
exceptionExpiry=missing

목적 권한 확대가 최소 권한 원칙과 예외 만료 기준을 만족하는지 확인한다.

정상 출력

Action: s3:GetObject
Resource: arn:aws:s3:::app-config/prod/*
Condition: aws:PrincipalArn pipeline-role
exceptionExpiry=2026-07-05

비정상 출력

Action: s3:*
Resource: *
Action: kms:Decrypt
Resource: *
exceptionExpiry=missing

판단 훈련 pipeline 권한이 배포 범위를 넘어섰고 만료 없는 예외라 침해 반경이 커진다.

즉시 완화 wildcard 권한을 즉시 되돌리고 필요한 read 권한만 한정한다.

영구 수정 IAM diff review gate, last-used review, exception expiry alert를 추가한다.

검증 기준 wildcard action/resource 0, break-glass ticket 만료일 존재, audit log에서 사용 권한 확인.

TERM

용어사전

보안 경계에서 반복적으로 등장하는 운영 용어를 정의, 증거, 오해, 관련 항목 기준으로 정리한다. 장애 중에는 용어 자체보다 해당 용어가 어떤 로그, 지표, 설정, 책임 경계와 연결되는지를 확인한다.

public ingressTERM
인터넷에서 접근 가능한 진입 표면. 운영에서는 public DNS, CDN/WAF distribution, LB listener로 확인한다. 흔한 오해는 "WAF가 있으면 내부 앱 노출도 괜찮다."라고 보는 것이다. 관련해서 edge, security group, external scan를 함께 본다.
WAFTERM
L7 요청 패턴을 기준으로 악성 또는 비정상 요청을 줄이는 통제. 운영에서는 WAF rule hit, false positive rate, deny log로 확인한다. 흔한 오해는 "WAF는 네트워크 방화벽과 같은 역할이다."라고 보는 것이다. 관련해서 firewall, rate limit, CDN를 함께 본다.
security groupTERM
stateful L4 허용 목록. 운영에서는 SG inbound/outbound diff, source, port로 확인한다. 흔한 오해는 "NACL과 동작 방식이 같다."라고 보는 것이다. 관련해서 NACL, L4, ingress를 함께 본다.
IAM principalTERM
권한을 부여받는 사람, 서비스, pipeline, workload identity. 운영에서는 principal, role assumption, last-used, policy diff로 확인한다. 흔한 오해는 "하나의 admin key로 운영해도 편하면 된다."라고 보는 것이다. 관련해서 role, least privilege, audit log를 함께 본다.
secret rotationTERM
비밀값을 revoke, 재발급, 배포, 영향 확인까지 교체하는 절차. 운영에서는 secret version, rotation date, consumer list로 확인한다. 흔한 오해는 "새 secret을 만들면 rotation이 끝난다."라고 보는 것이다. 관련해서 revoke, runtime injection, audit를 함께 본다.
CASE

장애/운영 시나리오

외부 공개 API를 신규 오픈한다. WAF rule과 rate limit을 먼저 적용하고, Load Balancer 뒤의 App은 private subnet에 둔다. IAM은 배포 권한과 운영 조회 권한을 분리하고, 인증 실패·차단·권한 거부 로그가 관측 시스템으로 들어오는지 확인한다.

Triage frame

보안 경계 장애는 프론트엔드에서 보인 증상 → 영향 범위 → 최근 변경 → Public ingress 증거 → 완화책 → 복구 검증 → 재발 방지 순서로 기록한다.

INCIDENT FLOW

처음 10분 DNS, CDN/WAF, LB listener, allowed path, rate limit 기준으로 영향 범위를 고정한다.

다음 30분 DNS record, LB listener, WAF rule, security group ingress 목록화 항목에서 증거를 모아 완화책을 실행한다.

종료 조건 보안 조치가 운영 절차로 남아야 한다.

증상Incident packet

기록할 내용 비정상 admin export 또는 외부 스캔 급증

판정 기준 actor, source IP, action, resource, WAF/auth log를 묶는다.

완화Incident packet

기록할 내용 token revoke, WAF rule tighten, role disable, egress block

판정 기준 임시 차단은 고객 영향과 만료 조건을 같이 기록한다.

RISK

자주 틀리는 판단

보안 경계에서 자주 틀리는 판단은 공개면 줄이기와 검증 질문의 책임 경계를 흐리는 데서 시작된다. 아래 신호가 보이면 설계, runbook, 답변 구조를 다시 점검한다.

  • 보안 그룹을 0.0.0.0/0으로 열고 WAF만 믿는다.
  • admin 권한을 장기 access key로 운영한다.
  • secret rotation을 배포 절차와 연결하지 않는다.
  • 차단 로그가 없어 false positive와 공격을 구분하지 못한다.
SUMMARY

총정리

보안 경계의 핵심은 프론트엔드에서 보이는 증상을 운영 계층의 증거와 연결해, 원인 후보를 줄이고 복구 기준을 명확히 말하는 것이다. 아래 표는 리뷰나 면접 직전에 마지막으로 훑는 압축본이다.

주제확인할 증거판단 기준
공개면 줄이기public DNS record, CDN/WAF distribution, LB listener, security group ingress, admin access pathApp/DB/cache/queue가 public endpoint 없이 private 경계 안에 있어야 한다.
WAF와 방화벽WAF rule hit, SG stateful rule, NACL stateless rule, firewall deny log, false positive rateL7 차단과 L4 허용 목록, subnet stateless 경계를 혼동하지 않아야 한다.
IAM과 secretprincipal, role assumption, policy diff, secret version, rotation date, last-used장기 key와 wildcard 권한은 예외 승인과 만료 조건이 필요하다.
검증 질문public ingress list, auth boundary, admin action log, egress allowlist, audit coverage공격 경로와 탐지 증거가 함께 설명되어야 한다.
실무 플레이북Public ingress → Identity / Secret → AuditabilityDNS record, LB listener, WAF rule, security group ingress 목록화; IAM policy diff, last-used, access review, break-glass ticket; secret manager version, rotation date, deploy consumer, log redaction
복구 기준비정상 admin export 또는 외부 스캔 급증보안 조치가 운영 절차로 남아야 한다.
