Q01

인증과 인가를 어떻게 분리해서 설명하나요?

Q05

CSRF와 CORS는 같은 문제인가요?

아닙니다. CSRF는 브라우저가 쿠키를 자동 전송하는 특성을 악용해 사용자의 의도 없는 상태 변경을 유도하는 공격이고, CORS는 브라우저가 cross-origin JS 접근을 제한하는 정책입니다.

꼬리질문꼬리질문 답변
SameSite=Lax면 CSRF가 완전히 해결되나요?SameSite=Lax는 많은 CSRF를 줄이지만 모든 흐름을 완전히 막지는 못합니다. 민감한 상태 변경에는 CSRF token, origin 검증, 재인증 같은 방어를 함께 둡니다.
Authorization header를 쓰면 CSRF 위험이 줄어드나요?Bearer token을 JS가 직접 붙이는 구조는 쿠키 자동 전송 CSRF 위험은 줄지만 XSS로 token이 탈취될 위험이 커집니다. 저장 위치와 XSS 방어를 같이 봐야 합니다.
CORS allow credentials는 왜 조심해야 하나요?credentials 허용 상태에서 origin을 넓게 열면 다른 origin이 인증 쿠키를 동반한 요청 결과를 읽을 수 있습니다. 정확한 allowlist와 Vary: Origin 처리가 필요합니다.

Q08

RBAC, ABAC, ReBAC를 어떻게 구분하나요?

RBAC는 역할 기반, ABAC는 속성 기반, ReBAC는 관계 기반 인가입니다. 실무에서는 role만으로 부족한 경우가 많아 tenant, owner, department, resource state 같은 속성을 함께 봅니다.
