Interactive Architecture

입력과 표현이 늘어나도 무너지지 않는 인터랙션 시스템 설계

INTERACTIVE WEB MASTERY · UPDATED 2026-10
START

인터랙션을 시스템으로 본다는 것

복잡한 인터랙션은 event handler와 animation을 많이 붙인 화면이 아니다. 입력, 의도, 상태, 시간, 표현, 부수 효과의 소유권이 명확하고 중단·역전·복구할 수 있는 시스템이다.

처음에는 클릭 한 번으로 열리는 gallery도 touch drag, keyboard, route transition, deep link, reduced motion, Canvas renderer가 추가되면 빠르게 복잡해진다. 각 기능이 DOM과 animation을 직접 바꾸면 서로의 진행 상태를 모르고 callback race, stale state, focus 손실이 생긴다. Architecture의 목적은 추상화를 많이 만드는 것이 아니라 변화가 다른 변화의 규칙을 깨지 않게 경계를 세우는 것이다.

CORE MODEL

RAW INPUT → NORMALIZED INTENT → DISCRETE STATE → CONTINUOUS SIGNAL → EFFECT / SCHEDULER → RENDERER → PERCEPTION으로 나눈다. Pointer·keyboard·scroll은 공통 의도로 번역되고, machine은 가능한 상태 전이만 허용한다. 시간에 따라 변하는 position과 velocity는 frame 신호로 계산하며, DOM·Canvas·WebGL renderer는 같은 의미 상태를 서로 다른 비용으로 표현한다. Navigation·network·focus·resource 생성은 명시적 effect로 실행하고 취소와 cleanup 계약을 가진다.

경계가 답해야 하는 질문예
입력을 누가 해석하는가?pointer swipe와 ArrowRight를 모두 NEXT intent로 변환
진실인 상태는 어디에 있는가?현재 slide index는 machine, drag 중 pixel 위치는 motion signal
시간을 누가 진행시키는가?하나의 scheduler가 timestamp로 spring을 update
화면을 누가 쓰는가?DOM renderer 또는 Canvas renderer 하나가 frame 결과를 반영
작업을 누가 취소·정리하는가?route leave가 animation, request, pointer capture와 RAF를 종료
01

모든 인터랙션을 같은 파이프라인으로 읽기

라이브러리보다 먼저 데이터가 어디서 와서 어떤 단위로 바뀌고 누가 소비하는지 그린다.

Inputpointer, key, scroll, resize, route, media query
NormalizeNEXT, DRAG_MOVE, CANCEL 같은 도메인 event
Stateidle, dragging, settling과 current index
Timeprogress, position, velocity, target
Effectfocus, history, load, analytics, resource
RenderDOM style, SVG, Canvas, WebGL scene
Perceive시각·보조 기술 상태와 다음 행동

각 화살표에는 계약이 있다. Pointer 좌표는 client pixel인지 local pixel인지, progress는 0–1 범위인지, index는 loop되는지, renderer는 position을 읽기만 하는지 명시한다. 단위와 방향이 없으면 mobile drag와 desktop wheel이 서로 다른 감각으로 동작하고 resize 뒤 snap target이 틀어진다.

Boundary contract 예

DRAG_MOVE는 raw pointer event가 아니라 { deltaPx, velocityPxPerMs, axis }다. Adapter가 pointer capture와 좌표 변환을 책임지고 machine은 device 종류를 모른다. Renderer는 이 값에서 계산된 normalized progress만 읽는다.

02

입력 정규화: 제스처가 아니라 의도를 전달하기

Pointer, touch, keyboard, wheel은 데이터 모양과 빈도가 다르다. 도메인 로직이 브라우저 event를 직접 알기 시작하면 입력 방식마다 규칙이 갈라진다.

Raw inputAdapter가 하는 일Domain intent
pointerdown/move/upcapture, local 좌표, threshold, velocity, cancel 처리DRAG_START / DRAG_MOVE / DRAG_END
ArrowLeft / ArrowRight방향·writing mode와 반복 입력 정책 적용PREVIOUS / NEXT
wheeldeltaMode 정규화, 축 선택, 누적 thresholdNAVIGATE 또는 SCRUB
scroll progresssection geometry를 0–1 progress에 mappingSET_PROGRESS
route/deep linkURL parameter validation과 index 변환GO_TO
prefers-reduced-motionmedia query 변경 감지SET_MOTION_MODE

Pointer capture와 cancel

Drag 중 pointer가 element 밖으로 나가도 같은 interaction이 event를 계속 받게 하려면 capture가 필요하다. 그러나 pointercancel, browser gesture, tab visibility 변화, element unmount에서 반드시 종료 경로가 있어야 한다. END만 있고 CANCEL이 없으면 isDragging이 영원히 남을 수 있다.

Renderer가 입력을 해석

Canvas click handler가 직접 index를 바꾸고, DOM button도 별도로 index를 바꾼다. threshold와 loop 규칙이 두 곳에서 달라진다.

의도 하나, adapter 여러 개

Canvas drag와 DOM button은 NEXT intent를 보낸다. Machine이 현재 상태와 경계 조건을 보고 같은 전이를 결정한다.

03

상태, 전이, guard와 불변식

Boolean 여러 개는 가능한 조합을 모두 허용한다. State machine은 지금 가능한 phase와 event를 제한해 불가능한 조합을 구조적으로 없앤다.

idle → dragging → settling → idle idle → navigating → loading? → revealing → idle any active state → cancelled → idle invariants: - currentIndex는 0..itemCount-1 범위다. - dragging이면 activePointerId가 존재한다. - reduced mode에서는 spatial transition이 시작되지 않는다. - destroyed 이후 event와 frame update는 상태를 바꾸지 않는다.
개념역할Gallery 예
State시스템이 현재 어느 phase인가idle, dragging, settling, loading
Event일어난 사실 또는 의도DRAG_END, NEXT, ASSET_READY, ROUTE_LEAVE
Guard전이를 허용하는 조건다음 item이 있고 navigation lock이 아님
Action동기적으로 state/context를 갱신targetIndex 계산, velocity 저장
Effect외부 세계와 상호작용asset load, focus, history update
Invariant어떤 순서에서도 항상 지켜야 할 규칙한 pointer만 drag 소유, index 범위 유지

중간 상태를 무조건 많이 만드는 것도 좋은 설계는 아니다. UI가 구분해서 행동해야 하거나 event 허용 규칙이 달라질 때 state로 승격한다. 단순히 opacity가 0.42라는 이유로 machine state를 만들지 않는다.

04

Discrete state와 continuous signal을 분리한다

“열려 있다”는 상태와 “현재 42% 열렸다”는 값은 변화 빈도와 사용 목적이 다르다.

종류예적합한 소유자관측 방식
Application statecurrent item, open/closed, selected optionreducer/state machine/store전이와 사용자 의미를 기록
Interaction contextactive pointer, drag origin, pending targetinteraction controllersession 동안 보존, 종료 시 정리
Frame signalposition, velocity, spring progressanimation/physics runtime매 frame renderer가 읽고 샘플링
Derived valueopacity, scale, parallax offset순수 mapping 함수source signal에서 계산, 별도 진실로 저장하지 않음

매 pointermove의 x를 React global state에 넣으면 application tree가 display frequency로 갱신될 수 있다. 반대로 current slide를 animation object 내부에만 두면 URL, focus, analytics와 DOM label이 실제 화면과 어긋난다. 의미 있는 전이는 application state에, 일시적 frame 값은 runtime에 두고 settle 시 target 결과를 확정한다.

하나의 진실, 여러 projection

currentIndex에서 DOM의 aria-current, pagination text, URL과 analytics가 파생된다. Drag position은 currentIndex를 임시로 덮어쓰지 않고 visual offset을 만든다. release 후 결정된 target index가 전이될 때만 의미 상태가 바뀐다.

05

Effect, race와 cancellation

Network, navigation, focus, timer, animation completion은 순수 state 계산 바깥의 effect다. 시작만 설계하고 취소·무효화 규칙을 두지 않으면 오래된 결과가 새 의도를 덮어쓴다.

세 가지 race

Race실패정책
Rapid toggleOPEN 완료 callback이 이미 시작된 CLOSE를 다시 open 처리animation을 reverse/retarget하거나 transition token으로 stale 완료 무시
Asset requestslide 2 요청이 늦게 도착해 이미 선택된 slide 5 preview를 교체AbortController 또는 request identity로 최신 intent만 commit
Route leave떠난 화면의 timer/RAF가 DOM과 state를 계속 갱신scope disposer가 timer, listener, frame, request, resource를 함께 종료

Cancellation은 “아무것도 하지 않음”이 아니다. Pointer cancel이면 원래 위치로 복귀할지 가까운 snap으로 정착할지, network cancel이면 loading state를 무엇으로 바꿀지, animation interrupt이면 현재 position·velocity를 새 target이 이어받을지 결정해야 한다.

effect contract start(context) → { cancel(reason), finished } finished result: { status: "completed" | "cancelled" | "failed", token, payload? } machine commits result only when token matches the active transition.
06

Renderer는 의미 상태를 표현하는 adapter다

DOM, SVG, Canvas와 WebGL이 state를 직접 결정하게 하지 않는다. Renderer는 snapshot과 frame signal을 받아 자신의 비용 모델로 표현한다.

계약설명실패하면
Inputsemantic snapshot + continuous frame valuesrenderer마다 다른 state 해석
Update바뀐 범위와 빈도를 명시모든 전이에 전체 redraw/re-render
OutputDOM style, canvas draw, scene transform만 변경renderer가 navigation·analytics까지 소유
Lifecyclemount, resize, pause, resume, disposeroute 재진입마다 listener·GPU 자원 누수
Fallback지원 실패에서도 같은 핵심 목표 유지graphics 초기화 실패가 전체 UI 실패

교체 가능성의 현실적인 범위

DOM과 Canvas renderer의 코드를 완전히 동일하게 만드는 것이 목표가 아니다. Input intent, 의미 상태와 완료 결과를 공유하고 각 renderer가 필요한 최적화를 내부에서 수행하게 한다. DOM renderer는 semantic element를 직접 제공할 수 있지만 Canvas renderer는 별도의 DOM accessibility layer가 필요하다.

DOM renderer

각 slide의 DOM identity와 focus를 유지하고 transform으로 offset을 표현한다. 콘텐츠와 interaction이 결합된 gallery에 적합하다.

Canvas/WebGL renderer

대량 visual tile이나 shader transition을 batch한다. 제목, control, current status는 DOM layer가 계속 소유한다.

07

소유권과 생명주기

누가 만들었는지가 누가 정리하는지를 결정한다. Listener, observer, timer, RAF, texture와 worker는 모두 명시적 owner가 필요하다.

Page scoperoute, deep link, page-level loading과 analytics를 소유한다.
Interaction scopemachine, input adapter, active pointer와 transition effect를 소유한다.
Renderer scopeDOM refs, canvas context, geometry, material, texture와 resize를 소유한다.
Asset scopecache, request dedupe, reference lifetime과 decode 결과를 소유한다.

React component lifecycle과 interaction lifecycle은 항상 같지 않다. Strict Mode의 개발 재실행이나 route transition 중 겹치는 mount에서도 setup/cleanup이 대칭이어야 한다. 외부 runtime을 ref로 숨기는 것만으로 ownership이 해결되지는 않는다.

08

업데이트 주기와 invalidation boundary

모든 데이터가 같은 빈도로 바뀌지 않는다. Event frequency, display frequency, application frequency를 구분해야 불필요한 작업과 state drift를 줄일 수 있다.

주기예Architecture 선택
Event frequencypointermove, wheel, sensor최신 sample 또는 필요한 history를 adapter에 저장
Display frequencyrequestAnimationFrame한 scheduler가 continuous state를 update하고 renderer 호출
Transition frequencyslide 확정, modal open, asset readymachine state와 semantic DOM 갱신
Background frequencyprefetch, telemetry batch사용자 입력과 frame을 막지 않는 낮은 우선순위

여러 component가 각각 RAF loop를 만들면 update 순서와 pause 정책이 흩어진다. 공유해야 하는 scene에서는 중앙 scheduler가 time source와 visibility pause를 관리하고 subsystem은 update/render hook을 등록한다. 반대로 단순 CSS transition까지 global engine에 넣으면 결합만 늘어난다.

Invalidation 기반 render

정적 scene은 매 frame 그릴 필요가 없다. Input, resize, asset ready, animation active일 때만 invalidated로 표시하고 필요한 frame을 요청한다. Ambient animation이 없다면 settle 뒤 loop를 정지한다.

09

Renderer가 달라도 의미와 목표는 같다

Architecture는 pointer와 pixel만 추상화해서는 부족하다. Keyboard·보조 기술 입력과 semantic output도 같은 도메인 모델에 연결한다.

Canvas hit test 결과가 곧 접근 가능한 control은 아니다. DOM control이 intent를 발생시키고 Canvas가 표현을 강화하는 구조가 필요하다. Focus, accessible name과 current state는 animation progress에서 추론하지 말고 semantic state에서 파생한다.

실패와 기능 저하를 architecture에 포함하기

WebGL, asset, network가 성공할 때만 존재하는 설계는 architecture가 아니라 demo다. 능력 확인과 실패 전이를 정상 흐름으로 다룬다.

Capability detection은 API 이름의 존재만 확인해서 끝나지 않는다. 실제 context/device 생성, 필수 feature와 limit, asset format 지원을 확인한다. 실패 시 사용자가 하던 일을 보존하고 낮은 renderer로 내려간다.

11

관측 가능하게 만들되 매 frame 로그하지 않는다

복잡한 interaction은 최종 화면만으로 race 원인을 찾기 어렵다. 의미 있는 전이와 effect lifecycle을 구조화해 기록한다.

기록필드 예목적
Transitionfrom, event, guard, to, timestamp불가능한 상태와 순서 재현
Effecttype, token, start, completed/cancelled/failedstale callback과 누락된 cancel 추적
Interaction summaryinput type, duration, target, result과도한 raw event 없이 UX 분석
Performance sampleactive mode, renderer, quality tier, slow frames어떤 구성에서 비용이 커졌는지 연결
Invariant failurestate snapshot과 최근 eventproduction에서 희귀 race 진단

Pointermove 좌표나 전체 state를 매 frame analytics로 보내지 않는다. 개인정보와 volume 비용이 커지고 성능도 해친다. 개발 trace와 제품 telemetry를 분리하고 전이·오류·완료 같은 의미 사건을 sampling한다.

테스트 피라미드

  1. 순수 mapping, reducer, guard와 invariant를 단위 테스트한다.
  2. 가짜 clock으로 spring/timeline의 cancel·retarget을 결정적으로 시험한다.
  3. DOM adapter와 renderer의 keyboard/focus/semantic 통합을 시험한다.
  4. 실제 브라우저에서 rapid input, pointercancel, resize, visibility, route leave를 실행한다.
  5. 대상 기기에서 renderer 성능과 fallback 과업 완료를 검증한다.
12

Gallery를 단계별로 설계하기

1단계 · 최소 의미 모델

items, currentIndex, phase, motionMode를 정의한다. NEXT, PREVIOUS, GO_TO, OPEN, CLOSE가 있고 index 범위와 focus 복귀가 불변식이다. 이 단계는 animation 없이 DOM button과 내용 전환만으로 완성한다.

2단계 · Drag adapter와 continuous state

Pointer adapter가 local delta와 velocity를 계산한다. Machine은 DRAG_START를 허용할지 판단하고 interaction runtime은 offset을 보존한다. DRAG_END에서 거리·속도·경계에 따라 target index를 결정하며 CANCEL은 명시된 복귀 정책을 따른다.

3단계 · Spring과 renderer

Spring은 현재 offset/velocity에서 target offset으로 정착한다. DOM renderer는 slide transform을, WebGL renderer는 mesh position/uniform을 갱신한다. Settle 완료 token이 여전히 active일 때만 currentIndex 전이를 확정한다.

4단계 · Route, asset과 focus

Index 확정 시 URL을 갱신하되 popstate로 들어온 GO_TO와 loop를 만들지 않는다. 다음 asset은 prefetch할 수 있지만 오래된 요청이 현재 preview를 덮지 못한다. Modal gallery라면 open/close state와 focus lifecycle을 소유한다.

5단계 · Failure와 reduced mode

GPU 실패 시 DOM renderer로 교체하고 currentIndex는 유지한다. Reduced motion에서는 drag input을 유지할 수 있지만 release 뒤 큰 spatial travel 대신 즉시 snap 또는 짧은 fade를 사용한다. Route leave는 모든 effect와 renderer를 destroy한다.

압박 상황기대 결과
NEXT를 10회 빠르게 입력정책에 따라 queue, coalesce 또는 retarget하며 index와 화면이 일치
Drag 중 pointercancelcapture 해제, dragging 종료, 정의된 target으로 복귀
Settle 중 resize새 viewport 기준 target 재계산, visual jump 없음
Asset load 중 route leaverequest와 completion 무효화, unmounted state update 없음
Animation 중 motion preference 변경현재 의미 target을 보존하고 안전한 variant로 정착
DECIDE

Architecture 설계 절차

  1. 사용자 목표와 의미 상태를 animation 없이 먼저 쓴다.
  2. Raw input과 domain intent를 분리하고 입력별 adapter를 정한다.
  3. State, event, guard, invariant로 불가능한 조합을 제거한다.
  4. Discrete state와 continuous signal의 owner와 update 빈도를 나눈다.
  5. Effect마다 start, completion, cancel, failure와 stale-result 정책을 쓴다.
  6. Renderer contract에 input, invalidation, resize, pause, dispose와 fallback을 명시한다.
  7. Accessibility output과 keyboard/focus lifecycle을 의미 상태에 연결한다.
  8. Failure fixture와 telemetry를 구현 전 설계에 포함한다.
추상화 기준

미래에 renderer를 바꿀 수도 있다는 이유로 모든 코드를 interface로 감싸지 않는다. 실제로 독립적으로 변하는 입력·상태·시간·renderer·effect 경계에만 추상화를 둔다. 한 구현만 있고 교체 요구가 없다면 먼저 명확한 모듈과 소유권으로 시작한다.

LAB

구현과 파괴 실습

Lab 1 · Boolean을 machine으로 바꾸기

isOpen/isAnimating/isDragging/hasError gallery를 transition table로 바꾼다. 도달 불가능한 조합, guard와 invariant를 표시하고 rapid toggle과 error 중 close를 시험한다.

Lab 2 · 입력 adapter 교체

Button, keyboard, pointer drag가 같은 NEXT/PREVIOUS/GO_TO event를 보내게 한다. Domain reducer test는 PointerEvent 없이 실행되어야 하며 RTL/writing direction 정책도 adapter 또는 mapping 경계에 둔다.

Lab 3 · DOM/Canvas renderer

같은 snapshot과 offset signal로 DOM과 Canvas renderer를 구현한다. Renderer 교체 뒤에도 URL, pagination, accessible current state와 keyboard 과업은 같아야 한다.

Lab 4 · Lifecycle torture test

Drag 중 unmount, settle 중 resize, hidden tab 복귀, request 역전, motion preference 변경, 20회 mount/unmount를 자동 fixture로 만든다. Listener·RAF·request·resource가 기준으로 돌아오는지 확인한다.

GATE

숙련 판정

  1. Raw browser event를 domain intent와 분리하고 좌표·단위 계약을 설명하는가?
  2. State, context, continuous signal, derived value를 서로 다른 수명과 빈도로 관리하는가?
  3. Guard와 invariant로 불가능한 boolean 조합을 제거하는가?
  4. Rapid input에서 cancel, reverse, retarget, queue, coalesce 중 정책을 명시하는가?
  5. DOM·Canvas·WebGL renderer가 의미 상태를 결정하지 않고 표현만 소유하는가?
  6. Network, focus, navigation, animation completion의 stale result를 막는가?
  7. Keyboard·screen reader·reduced motion에서도 같은 목표와 상태를 제공하는가?
  8. Unmount, route leave, visibility, resize와 renderer failure 뒤 resource가 정리되는가?
완료 상태

새 라이브러리를 만났을 때 architecture 전체로 채택하지 않는다. Input adapter인지, state runtime인지, animation scheduler인지, renderer인지, effect 도구인지 배치하고 기존 owner·lifecycle·fallback 계약에 맞는지 판단할 수 있어야 한다.
