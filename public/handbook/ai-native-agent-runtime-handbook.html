테스트·리뷰·릴리스
자동화

AI agent는 테스트 후보와 릴리스 문서를 잘 만들 수 있습니다. 하지만 최종 판단은 실제 검증 명령, 코드 리뷰, 수동 QA, 롤백 조건으로 닫아야 합니다.

REL-00

마지막 단계의 AI Native 기준

작업의 끝은 AI가 요약을 잘했다는 것이 아니라, 다음 사람이 같은 검증을 재실행할 수 있는 상태입니다. AI를 Test Critic, Code Review Assistant, Release Scribe로 나누어 사용합니다.

Agent맡길 일사람이 확정할 일
Test Critic빠진 테스트와 경계값 찾기위험도 높은 테스트 선택
Code Review Assistantdiff 요약, 잠재 버그 후보실제 코드 리뷰 판단
Release Scribe릴리스 노트, QA 체크리스트 초안출시 여부와 롤백 조건
REL-01

테스트·릴리스 AI Loop

RELEASE LOOP diff 제공 -> 테스트 후보 생성 -> 검증 명령 실행 -> 리뷰 위험 기록 -> 릴리스 노트 -> 롤백 조건 
prompt:
  role: "Test Critic"
  task: "백오피스 환불 승인 기능 diff에서 빠진 테스트와 수동 QA 항목을 찾아줘"
  context:
    - "환불 요청 목록 UI"
    - "환불 승인/반려 API"
    - "감사 로그 저장 로직"
  output:
    - missing_tests
    - manual_qa
    - release_risks
    - rollback_triggers
USE

실제로 이렇게 사용한다

마지막 단계에서 AI에게 “리뷰해줘”라고만 하면 일반론이 나옵니다. diff 요약, 변경 파일, 이미 실행한 테스트를 주고 누락 테스트와 릴리스 위험을 찾게 해야 합니다.

내 입력:
백오피스 환불 승인 기능 구현이 끝났어.
변경 파일:
- RefundRequestTable.tsx
- RefundDetailDrawer.tsx
- refundRequests.controller.ts
- refundRequests.service.ts
- migration_create_refund_workflow.sql
- refundRequests.test.ts

실행한 검증:
- npm test -- refund 통과
- npm run build 통과

너는 Test Critic이자 Release Scribe야.
아래를 만들어줘.
1. 빠진 테스트 후보
2. 수동 QA 목록
3. 릴리스 위험
4. 롤백 조건
5. release note 초안
AI 출력 예사람의 결정
이미 처리된 요청 재승인 테스트가 빠짐backend test에 추가
대량 일괄 승인 테스트 필요이번 범위 제외. 일괄 승인이 없으므로 follow-up으로 이동
환불 승인 5xx 또는 결제사 실패가 증가하면 rollback롤백 트리거로 채택
verification-log.md:
commands:
  - command: "npm test -- refund"
    result: "pass"
  - command: "npm run build"
    result: "pass"
manual_qa:
  - "refund_manager approves requested refund"
  - "cs_operator sees read-only detail"
  - "already processed request shows specific error"
rollback_triggers:
  - "refund approval 5xx > 1%"
  - "payment provider refund failures spike"
개념

릴리스 단계의 AI Loop는 요약문 생성이 아니라 검증 증거 정리입니다. AI가 만든 릴리스 노트보다 실제 실행한 명령과 롤백 조건이 더 중요합니다.

REL-02

테스트 선택 예시

분류테스트선택 이유
Frontendfilter changes refresh refund list운영자가 요청을 찾는 핵심 흐름
Frontendapprove confirm 중 버튼 disabled중복 요청과 실수 승인 방지
Backendrefund_manager가 아니면 403권한 핵심 케이스
Backendalready_processed 재처리 방지데이터 무결성
Integration승인 성공 시 상태 변경, decision, audit log가 함께 저장핵심 운영 흐름
REL-03

릴리스 기록 예시

release_note:
  feature: "backoffice refund approval"
  included:
    - "refund request table and detail drawer"
    - "refund approve and reject API"
    - "audit log recording"
  verification:
    - "npm test -- refund"
    - "npm run build"
    - "manual QA: approve, reject, forbidden, already processed"
  rollback_triggers:
    - "refund approval 5xx > 1%"
    - "payment provider failure spike"
  rollback:
    - "disable approve/reject entry point"
    - "keep existing refund request states unchanged"
