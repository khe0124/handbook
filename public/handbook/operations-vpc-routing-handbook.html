NET-00

CIDR과 subnet

VPC CIDR은 RFC 1918 대역을 쓰더라도 사내망, 고객사망, peering, VPN, Private Endpoint와 겹치면 나중에 막힌다. subnet은 public, private, data 계층으로 나누고 AZ 확장과 reserved IP를 고려한다.

OPERATIONS DECISION

운영 질문 CIDR과 subnet 설계가 미래 연결을 막지 않는다는 것을 어떻게 검증하는가?

확인할 증거 VPC CIDR, subnet mask, AZ allocation, reserved IP, peering/VPN/PrivateLink overlap check

판단 기준 사내망·고객사망·확장 예정 대역과 겹치지 않아야 한다.

배제 확인 CIDR과 subnet를 원인 후보에서 배제하려면 어떤 확인 결과가 필요한가?

확인 위치 CIDR registry, route plan, IPAM, cloud subnet readback

명령 해석 주소 계획이 문서와 실제 cloud subnet에서 일치해야 한다.

임시 완화와 영구 수정 고객사 VPN 연결 시 CIDR overlap 발견 기준으로 영향 범위를 좁히고, NAT 또는 재주소화 같은 임시 우회와 장기 CIDR 재설계를 분리한다.

NET-01

route table

route table은 패킷의 다음 hop을 정한다. 0.0.0.0/0이 Internet Gateway인지 NAT Gateway인지, 고객사 CIDR이 VPN Gateway로 가는지, 더 구체적인 prefix가 Longest Prefix Match로 우선되는지 확인한다.

OPERATIONS DECISION

운영 질문 패킷의 다음 hop이 의도한 route table로 결정되는가?

확인할 증거 destination prefix, target, propagated route, NAT/IGW/TGW/VGW, longest prefix match

판단 기준 0.0.0.0/0보다 구체적인 prefix가 올바른 target으로 가야 한다.

배제 확인 route table를 원인 후보에서 배제하려면 어떤 확인 결과가 필요한가?

확인 위치 route table readback, effective route, propagated route, packet path diagram

명령 해석 선언한 경로와 실제 effective route가 같아야 한다.

임시 완화와 영구 수정 private subnet 서버가 외부 API timeout 기준으로 영향 범위를 좁히고, route target, NAT 상태, return path를 나누어 수정한다.

NET-02

ingress와 egress

ingress는 외부에서 들어오는 경로이고 egress는 내부에서 나가는 경로다. private subnet의 서버가 외부 API를 호출하려면 NAT, DNS, outbound security group, NACL, return path가 모두 맞아야 한다.

OPERATIONS DECISION

운영 질문 ingress와 egress가 source/destination/port 기준으로 분리 검증되는가?

확인할 증거 source IP, destination IP, port, protocol, SG inbound/outbound, NACL ephemeral port, return path

판단 기준 outbound 허용만으로 성공이 아니며 응답 경로까지 맞아야 한다.

배제 확인 ingress와 egress를 원인 후보에서 배제하려면 어떤 확인 결과가 필요한가?

확인 위치 flow log, firewall decision, SG/NACL rule, NAT metric, DNS query log

명령 해석 REJECT 위치가 route인지 policy인지 DNS인지 구분한다.

임시 완화와 영구 수정 외부 결제 API 호출 timeout과 NAT bytes 급증 기준으로 영향 범위를 좁히고, egress allowlist, retry 제한, NAT route 조정을 임시 완화로 검토한다.

NET-03

Private Endpoint

DB, object storage, managed API를 인터넷으로 나가지 않고 호출해야 할 때 Private Endpoint 또는 PrivateLink 계열을 검토한다. 이때 DNS override와 endpoint policy까지 함께 봐야 트래픽이 의도한 사설 경로로 흐른다.

OPERATIONS DECISION

운영 질문 Private Endpoint가 실제로 사설 경로를 강제하는가?

확인할 증거 private DNS override, endpoint policy, route table, public access disabled, flow log

판단 기준 endpoint 생성만으로 충분하지 않고 DNS가 사설 IP를 반환해야 한다.

배제 확인 Private Endpoint를 원인 후보에서 배제하려면 어떤 확인 결과가 필요한가?

확인 위치 nslookup/dig, endpoint connection status, flow log, storage/DB network setting

명령 해석 public endpoint로 해석되면 Private Endpoint 설계가 동작하지 않는다.

임시 완화와 영구 수정 Private Endpoint 생성 후에도 public egress 비용 발생 기준으로 영향 범위를 좁히고, DNS override와 endpoint policy를 수정하고 public access 차단을 검증한다.

CHECK

실무 체크리스트

VPC·Subnet·Routing·NAT 체크리스트는 CIDR과 subnet, route table, ingress와 egress, Private Endpoint에서 놓치기 쉬운 운영 증거를 작업 전후로 고정하기 위한 검토표다. 각 항목은 프론트엔드 증상, 배포 승인, 운영 인수에서 같은 기준으로 다시 확인한다.

  • CIDR overlap과 reserved IP를 설계 단계에서 확인한다.
  • public, private, data subnet의 route table을 분리한다.
  • ingress와 egress를 각각 source, destination, port, policy로 검증한다.
  • Private Endpoint 사용 시 DNS override와 endpoint policy를 같이 본다.
설계작업 단계

필수 산출물 목적, 영향 범위, 비목표, owner

차단 기준 영향 범위가 사용자·시스템·비용 기준으로 설명되지 않음

변경작업 단계

필수 산출물 diff, 승인 기록, 검증 명령

차단 기준 production 변경과 staging 검증의 차이가 설명되지 않음

복구작업 단계

필수 산출물 rollback 또는 forward fix, 담당자, 예상 시간

차단 기준 실패 시 되돌릴 수 없는데 사전 승인과 공지가 없음

PLAYBOOK

실무 플레이북

VPC·Subnet·Routing·NAT 플레이북은 VPC ROUTING EVIDENCE PLAYBOOK 기준으로 증상, 범위, 최근 변경, 계층별 증거를 연결한다. 목표는 명령어를 많이 아는 것이 아니라 어느 가설을 버리고 어떤 완화책을 선택할지 설명하는 것이다.

VPC ROUTING EVIDENCE PLAYBOOK 1 symptom → 2 scope → 3 recent change → 4 evidence
→ 5 mitigation → 6 verification → 7 runbook diff
1 · 증상symptom
무엇이 안 되는가를 사용자 관점 한 문장으로. "느리다"가 아니라 어떤 요청이 언제부터 어떻게 실패하는지 적는다
2 · 영향 범위scope
전체인가 일부인가. region·tenant·경로·클라이언트 중 무엇으로 갈리는지가 가설의 절반을 지운다
3 · 최근 변경recent change
직전 배포, 설정·권한 변경, 인증서·route 교체를 같은 시간축에 올린다. 대부분의 장애는 최근 변경에서 온다
4 · 증거evidence
선언한 route가 아니라 provider가 계산한 effective route를 본다. SG·NACL은 양방향으로, flow log는 REJECT 기준으로 확인한다
5 · 완화mitigation
잘못된 route나 규칙을 이전 상태로 되돌린다. 임시로 여는 허용 규칙에는 만료 시각을 함께 건다
6 · 복구 검증verification
완화가 실제로 먹혔는지 같은 증거로 다시 확인한다. 사용자 경로를 한 번 통과시켜야 끝난 것이다
7 · 런북 갱신runbook diff
이번에 내린 판단을 문서에 되돌린다. 다음 사람이 같은 순서를 다시 발명하지 않게 하는 단계
CIDR / Subnet운영 표면

볼 증거 VPC CIDR, subnet route table, AZ, reserved IP, overlap check

판단 기준 나중에 peering/VPN/PrivateLink가 막히는 CIDR을 초기에 제거한다.

Ingress / Egress운영 표면

볼 증거 source, destination, port, protocol, SG, NACL, route target

판단 기준 outbound와 return path를 함께 검증한다.

Flow evidence운영 표면

볼 증거 VPC Flow Logs, firewall log, NAT metric, DNS resolution

판단 기준 허용했다고 믿는 경로와 실제 패킷 경로가 일치해야 한다.

라우팅확인 단계

명령·확인 위치 route table destination/target, longest prefix match, propagated route 확인

해석 기준 0.0.0.0/0와 더 구체적인 prefix의 우선순위를 본다.

정책확인 단계

명령·확인 위치 security group outbound/inbound, NACL ephemeral port, firewall rule

해석 기준 SG는 stateful, NACL은 stateless라는 차이를 반영한다.

패킷 증거확인 단계

명령·확인 위치 flow log ACCEPT/REJECT, NAT bytes, DNS query log

해석 기준 막힌 위치가 route인지 policy인지 DNS인지 분리한다.

Route miss심화 장애 패턴

관찰 신호 destination route 없음, 잘못된 NAT/IGW/TGW target, 더 구체적인 route 우선

판정 기준 패킷이 어느 next hop으로 가는지부터 확인한다.

Policy block심화 장애 패턴

관찰 신호 SG outbound, SG inbound, NACL inbound/outbound, firewall deny

판정 기준 stateful과 stateless 정책을 구분한다.

DNS path심화 장애 패턴

관찰 신호 private DNS override 누락, public endpoint 해석, resolver rule 불일치

판정 기준 네트워크가 맞아도 이름이 다른 경로를 가리키면 실패한다.

Return path심화 장애 패턴

관찰 신호 peer route 누락, asymmetric routing, ephemeral port 차단

판정 기준 요청 경로와 응답 경로가 모두 열려야 한다.

PRACTICE

출력 판독 훈련

VPC·Subnet·Routing·NAT는 개념을 아는 것보다 실제 출력에서 정상과 비정상을 구분하는 훈련이 중요하다. 아래 lab은 명령, 출력, 판단, 완화, 영구 수정을 한 번에 연결한다.

PRACTICE LAB 01 · Route table egress 판독

private subnet batch가 외부 결제 API를 호출하지 못한다.

Command / Query

aws ec2 describe-route-tables --filters Name=association.subnet-id,Values=subnet-private-a

목적 0.0.0.0/0가 NAT로 향하는지, 더 구체적인 prefix가 잘못 잡히지 않았는지 확인한다.

정상 출력

DestinationCidrBlock: 0.0.0.0/0
NatGatewayId: nat-12345
State: active

비정상 출력

DestinationCidrBlock: 10.0.0.0/16
GatewayId: local
State: active
# 0.0.0.0/0 라우트 없음

판단 훈련 비정상에는 VPC CIDR을 향하는 local 라우트만 있고 0.0.0.0/0 default route가 없다. egress next hop이 정의되지 않아 외부 API 호출이 실패한다. local 라우트는 VPC CIDR 대상이며 0.0.0.0/0에는 붙지 않는다.

즉시 완화 임시로 올바른 NAT route를 연결하고 결제 API allowlist 영향도 확인한다.

영구 수정 subnet별 route table review와 egress dependency map을 release checklist에 추가한다.

검증 기준 flow log ACCEPT, NAT bytes 증가, 결제 API synthetic check 성공.

TERM

용어사전

VPC·Subnet·Routing·NAT에서 반복적으로 등장하는 운영 용어를 정의, 증거, 오해, 관련 항목 기준으로 정리한다. 장애 중에는 용어 자체보다 해당 용어가 어떤 로그, 지표, 설정, 책임 경계와 연결되는지를 확인한다.

CIDRTERM
VPC와 subnet의 IP 주소 범위 표기. 운영에서는 VPC CIDR, subnet mask, overlap check로 확인한다. 흔한 오해는 "RFC1918 대역이면 언제나 안전하다."라고 보는 것이다. 관련해서 subnet, peering, VPN를 함께 본다.
route tableTERM
패킷의 다음 hop을 결정하는 라우팅 규칙. 운영에서는 destination prefix, target, effective route로 확인한다. 흔한 오해는 "subnet 이름이 private면 인터넷 경로가 없다."라고 보는 것이다. 관련해서 NAT Gateway, IGW, longest prefix match를 함께 본다.
ingressTERM
외부에서 서비스 안으로 들어오는 경로. 운영에서는 source IP, destination port, SG inbound, WAF log로 확인한다. 흔한 오해는 "LB만 있으면 ingress 통제는 끝난다."라고 보는 것이다. 관련해서 egress, security group, WAF를 함께 본다.
egressTERM
서비스 내부에서 외부로 나가는 경로. 운영에서는 NAT metric, SG outbound, DNS query log, flow log로 확인한다. 흔한 오해는 "outbound rule만 열면 응답도 보장된다."라고 보는 것이다. 관련해서 return path, NACL, NAT Gateway를 함께 본다.
Private EndpointTERM
관리형 서비스를 public internet 없이 사설 경로로 접근하게 하는 연결. 운영에서는 private DNS, endpoint policy, public access disabled로 확인한다. 흔한 오해는 "endpoint 생성만으로 트래픽이 사설화된다."라고 보는 것이다. 관련해서 PrivateLink, DNS override, flow log를 함께 본다.
CASE

장애/운영 시나리오

private subnet의 배치 작업이 외부 결제 API를 호출하지 못한다. route table의 0.0.0.0/0이 NAT로 향하는지, security group outbound와 NACL 응답 포트가 열려 있는지, DNS가 public endpoint를 해석하는지, return path가 가능한지 순서대로 확인한다.

종료 조건 다음 외부 연동 전에 경로와 비용을 사전 리뷰한다.

RISK

자주 틀리는 판단

VPC·Subnet·Routing·NAT에서 자주 틀리는 판단은 CIDR과 subnet와 Private Endpoint의 책임 경계를 흐리는 데서 시작된다. 아래 신호가 보이면 설계, runbook, 답변 구조를 다시 점검한다.

  • subnet 이름에 private가 붙었다고 인터넷이 차단됐다고 단정한다.
  • outbound만 열고 return path와 ephemeral port를 보지 않는다.
  • NAT 비용과 가용성을 고려하지 않는다.
  • Private Endpoint를 만들고 DNS 설정을 놓친다.
SUMMARY

총정리

VPC·Subnet·Routing·NAT의 핵심은 프론트엔드에서 보이는 증상을 운영 계층의 증거와 연결해, 원인 후보를 줄이고 복구 기준을 명확히 말하는 것이다. 아래 표는 리뷰나 면접 직전에 마지막으로 훑는 압축본이다.
