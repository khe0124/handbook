03-00

통합 목적

기존 03~06 문서는 모두 같은 결정을 다른 각도에서 반복했습니다. 성장 진단은 노선 선택으로 이어지고, 노선 선택은 시장 요구로 검증되며, 시장 갭은 산출물 우선순위로 닫혀야 합니다. 그래서 이 문서는 다섯 문서를 하나의 실행 루프로 합칩니다.

이전 문서통합 후 역할남길 핵심
강점·취약점 진단현재 좌표와 개선 우선순위이미 팔 수 있는 강점과 증거가 부족한 취약점 분리
노선 A · PM 겸 개발자선택 가능한 포지셔닝 카드제품 판단과 구현 판단을 함께 말하는 지원처에 사용
노선 B · 제품형 프론트엔드기본 주력 노선React/Next/TypeScript, B2B, 성능, API 경계, 백엔드 확장
시장 요구 분석노선 검증 근거표본 기반 통과선과 차별선, stale 방지 갱신 규칙
산출물 정리실행 결과물PM·개발자·UX 관점의 재사용 가능한 증거 파일
읽는 법

이 페이지는 순서대로 읽되, 완료 기준은 요약이 아니다. 마지막에 산출물 하나가 실제 파일명과 공개 가능 범위를 가진 상태로 정해져야 한다.

03-01

현재 좌표 — 지금 어디에 서 있나

현재 포지션은 “디자인 기반의 7년차 프론트엔드”에서 “제품형 프론트엔드 + 백엔드 도메인 확장”으로 이동 중입니다. 핵심은 백엔드 전환을 과장하는 것이 아니라, 프론트엔드 강점 위에 API 계약, 도메인 상태, 트랜잭션 판단을 얹는 것입니다.

좌표이미 강한 증거주의할 경계
제품형 프론트엔드제품환경평가/LCCI, pople, TaaS, Greenery 웹사이트, React/Next/TypeScript, Form, Data Grid, i18n, 성능·SEO 운영정량 수치가 없는 성능 개선은 기법과 재현 조건까지만 말한다.
B2B·SaaS 어드민권한, 대량 데이터, OCR, PDF/Excel, 운영자 UX, 감사 가능성서버 정책과 도메인 규정을 직접 소유한 것처럼 말하지 않는다.
풀스택 확장광명시 플랫폼에서 FE와 Spring Boot 백엔드 도메인·트랜잭션을 함께 다룬 경험CI/CD·클라우드 인프라 미관여, 공통 auth/RBAC 팀 소유 경계를 밝힌다.
AI NativeAI와 함께 task spec, 구현 초안, 테스트, 문서화, 검증 루프를 운영한 경험AI가 만든 결과를 검증 없이 썼다는 인상을 주지 않는다.
한 줄 포지셔닝복잡한 B2B/SaaS 업무 화면을 React/Next/TypeScript로 오래 구현·운영했고, 최근에는 거래 도메인에서 API 계약과 백엔드 트랜잭션 경계까지 확장한 제품형 프론트엔드 개발자.
03-02

강점·취약점 지도

강점은 더 공부할 주제가 아니라 더 잘 보이게 만들 자산입니다. 취약점은 약점 고백으로 끝내지 않고, 산출물과 검증 방법으로 바꿉니다.

축상태다음 행동
복잡한 업무 UI강점. 대량 입력, 권한, 상태 전이, 리포트 경험이 많다.제품환경평가나 pople에서 “업무 실패 회복” 사례를 한 장짜리 케이스로 만든다.
성능 최적화경험은 있으나 정량 증거가 부족하다.대형 폼 리렌더링 또는 웹사이트 성능 개선을 측정-원인-조치-결과 회고로 작성한다.
백엔드 도메인도메인·트랜잭션 경험은 강점으로 전환 가능하다.VRC 원장, 비관락, 상태 전이, 테스트를 ADR 형태로 정리한다.
리드·멘토링시니어 리드 공고에서는 증거가 상대적으로 약하다.지금은 강한 IC로 포지셔닝하고, 리뷰·문서·작업 분해 사례를 보조 증거로 쓴다.
외부 산출물개인 브랜드와 공개 증거가 부족하다.성능 회고, 트랜잭션 ADR, AI Native 검증 루프 중 하나를 공개 가능한 글로 변환한다.
03-03

노선 선택 — A/B를 나누되 한 몸으로 운용

노선은 정체성이 아니라 지원 전략입니다. 모든 공고에 같은 사람으로 보이려 하지 말고, 공고가 검증하는 위험에 맞춰 앞세울 증거를 바꿉니다.

공고 신호선택할 노선앞세울 증거숨기거나 낮출 것
제품 정의, 사용자 흐름, 이해관계자 조율, 작은 팀노선 A · PM 겸 개발자스펙 갭 분석, 사용자 여정 맵, 우선순위 판단, 구현 가능성 검토기획 총괄처럼 보이는 표현
React/Next/TypeScript, 성능, 테스트, B2B, API 경계노선 B · 제품형 프론트엔드대형 폼, Data Grid, 권한, i18n, 웹사이트 운영, API 오류 UX백엔드 전환을 주력처럼 과장하는 표현
FE+DB, FE+Backend, 풀스택 성향노선 B 확장형gks-car-be 도메인·트랜잭션, FE/API 계약, 상태 동기화인프라·공통 플랫폼을 직접 운영한 듯한 표현
AI 활용, 자동화, 생산성, LLM 기능AI Native 보조 카드task spec, generated diff, test output, rejected suggestion, README모델명이나 도구 사용량만 앞세우는 표현
03-A

노선 A · PM 겸 개발자 카드

이 노선은 “PM도 할 수 있다”가 아니라 개발자가 제품 판단에 개입해 요구의 빈틈을 줄였다는 증거가 있을 때만 씁니다.

면접 메시지쓸 증거안전 문장
요구를 그대로 구현하지 않고 업무 흐름으로 재구성한다.제품환경평가 실패 회복 스펙 갭, 광명 도메인 시장 라이프사이클 여정 맵“최종 제품 결정을 총괄했다기보다, 구현 가능성과 사용자 흐름 관점에서 빈틈을 드러냈습니다.”
핵심 경로와 부가 기능을 나눌 수 있다.일정 압박 시 우선순위 판단, MVP/후속 범위 분리“팀 합의 안에서 핵심 경로를 지키기 위한 판단 근거를 제공했습니다.”
사용자 흐름과 구현 비용을 함께 본다.정보구조, 상태별 화면, 오류 회복 UX, API 계약“화면을 예쁘게 만드는 것보다 사용자가 업무를 끝내는 조건을 먼저 정리했습니다.”
03-B

노선 B · 제품형 프론트엔드 카드

기본 주력 노선은 제품형 프론트엔드입니다. 시장의 통과선인 React/TypeScript/Next를 이미 넘었고, 차별선은 성능·테스트·B2B 업무 UI·백엔드 경계 이해입니다.

면접 메시지쓸 증거보강할 것
복잡한 업무를 사용자가 끝낼 수 있는 화면으로 바꾼다.제품환경평가, pople admin, TaaS admin, 권한·테이블·폼·리포트업무 실패 회복 before/after
화면 상태와 API 계약을 함께 본다.axios interceptor, 인증 만료 UX, validation, pagination/filter, 파일 업로드/다운로드API error contract 예시
성능과 운영 품질을 릴리스 기준으로 본다.Greenery 웹사이트 3.5년 운영, SEO/AEO, 성능 개선, stg/prod 배포정량 성능 측정 1건
백엔드 확장은 도메인 경계 중심으로 말한다.VRC 원장, 비관락, 트랜잭션, QueryDSL, 통합 테스트트랜잭션 ADR
03-04

시장 요구·이력 갭 맵

시장 분석은 절대 비율이 아니라 방향을 읽는 표본입니다. 기존 조사에서는 5년+ 프론트엔드 공고에서 React, TypeScript, Next.js/SSR, 성능 최적화가 통과선 또는 차별선으로 반복됐고, AI 활용은 아직 공고 자격요건보다 차별화 카드에 가깝습니다.

요구현재 상태판정액션
React·TypeScript·Next·상태관리충분한 실무 경험통과선 충족경력 첫 화면에서 선명하게 보이게 한다.
성능 최적화경험은 있으나 공개 가능한 수치 부족1순위 갭성능 개선 회고를 최우선 산출물로 만든다.
테스트·품질Vitest·MSW·Playwright 경험, QA 관점 보유강화 가능테스트 전략을 위험 기반으로 설명하는 카드 작성
React Native·웹+앱HEMS 경험보조 차별점RN 우대 공고에서만 앞쪽으로 올린다.
백엔드·DB 이해gks-car-be 도메인 구현 경험차별점풀스택 성향 공고에서 API/트랜잭션 증거로 사용
리드·멘토링증거 부족지금은 약점시니어 리드보다 강한 IC 포지셔닝 유지
갱신 규칙

지원 시즌 시작 전 또는 6주 이상 지난 경우 공고 10건 이상을 새로 읽고 이 표를 갱신한다. “시장 전체”라고 말하지 말고 “최근 표본 기준”이라고 표현한다.

03-05

산출물 지도 — 이력을 증거로 바꾸기

산출물은 자랑거리가 아니라 검증 가능한 증거입니다. 하나의 프로젝트에서 PM, 개발자, UX 관점의 산출물이 동시에 나올 수 있지만, 역할을 부풀리면 안 됩니다.

우선순위산출물소스완료 기준
1성능 개선 회고제품환경평가 대형 폼, Greenery 웹사이트, 코드 스플리팅증상, 측정, 원인, 조치, 전후 증거가 있다.
2트랜잭션·원장 ADRgks-car-be VRC 원장, 비관락, 상태 전이맥락, 결정, 대안, trade-off, 테스트 증거가 있다.
3스펙 갭 분석 + 사용자 여정 맵제품환경평가 실패 회복, 광명 도메인 시장 라이프사이클요구, 발견한 갭, 제안, 구현, 결과가 한 장에 있다.
4디버깅 회고상태·동시성·성능 버그 중 하나재현, 가설, 기각, 근본원인, 재발방지가 있다.
5AI Native 검증 루프 공개물task spec, generated diff, test output, rejected suggestionAI가 한 일과 사람이 승인한 판단이 분리된다.
파일명 규칙career/artifacts/{pm|dev|ux}-{project}-{topic}.md 로 저장한다. 공개 가능, 익명화 필요, 구두 설명만 가능, 비공개를 머리말에 표시한다.

90일 실행 로드맵

새 일을 늘리는 것이 아니라 이미 있는 이력을 증거로 바꾸는 순서입니다. 가장 효과가 큰 산출물부터 하나씩 닫습니다.
